## 面试答题公式（每题都按这条骨架讲）

**这是本套文档所有章节的统一叙事骨架**，也是面试答题的标准动作。不管抽到哪道题，先在脑子里过一遍这五步：

1. **为什么会有这个问题**（30 秒）—— 讲一个具体场景 / 一次线上故障 / 一次撞墙的实测数据。**开场先立现场，别上来就讲实现**。
   - 反例："我们的循环控制是 eino 默认 20 轮，可配 MaxStep..."（面试官心里：跟我说这些做什么）
   - 正例："跨产品根因定位一次要 30+ 轮工具调用，早期我们默认 20 轮，用户经常撞上 `ErrExceedMaxIterations`——**运维场景最需要结论的复杂问题恰恰最容易撞上限**，一整轮几十次调用白费。所以我们才做了 MaxStep 分级 + 强制收敛。"

2. **当时的选择**（1 分钟）—— 讲你**为什么选 A 不选 B/C**。技术方案往往有多条路，讲清"为什么不选另外几条"比讲"选了什么"更有价值。
   - 例："上下文超限时理论上可以：① 直接失败 ② 切更大模型 ③ 摘要旧历史 ④ 压缩当前请求原地重试。我们选④是因为切模型有成本、摘要要多调一次 LLM、直接失败伤用户，而④只在真撞上限时才付出一次压缩成本。"

3. **现在的做法**（1~2 分钟）—— 讲实现骨架，标代码位置。**不要念代码**，讲清结构和关键决策点。

4. **代价 / 权衡**（30 秒）—— 主动说这个方案付出了什么、放弃了什么。**主动自曝短板比被追问出来强 10 倍**。
   - 例："这套自适应重试目前只覆盖 Generate，Stream 直接透传——AG-UI 主链路是流式，所以这个兜底在生产上其实很少触发，这是我们已知的 P0 缺口。"

5. **下一步怎么改**（30 秒）—— 讲下一版怎么补，最好带 ROI 判断（成本、收益、优先级）。

**为什么坚持这五步**：
- 面试官对"我们做了 X"无感，对"我们撞了一次 Y，代价是 Z，所以做了 X，现在还有 W 没解决"会立刻追问下去。
- 前三步证明**你参与过决策**，第四步证明**你有工程判断力**，第五步证明**你有 owner 意识**。这三样是区分「读过代码」和「做过项目」的分水岭。

**文档编排上如何配合这个公式**：
- **07/08 题库**：每题最前面有一段"**为什么会有这个问题**"，直接对应第 1 步；后面的四家对照/亮点/不足/改进对应第 2-5 步。
- **01-04 机制篇**：每个大节开头有"**为什么要做这一块**"导语，讲清这块投入的背景。
- **05-06 场景篇**：每个 Agent 除了业务痛点，还有"**关键决策**"小节，讲清"为什么选 A 不选 B"。
- **11 优化编年史**：整篇按【现象】→【根因】→【优化动作】→【代价/权衡】四段写，是这套公式的**样板文本**，看不明白公式时直接翻 11 找参照。

## 三条必须先立住的口径（面试自曝，避免被击穿）

面试中主动说明以下三点，比被追问出来要好得多：

| 对外常见说法 | 代码事实 | 建议表述 |
|---|---|---|

## 一分钟电梯陈述（面试开场用）

> TCUM-AI 是腾讯云统一运维（TCUM）的 AI Agent 平台，基于 CloudWeGo eino ADK 构建，4 个服务进程、15 个生产 Agent、12 个子 MCP Server 约 128 个工具、48 个声明式 Skill。
>
> 它不是"一个大模型 + 一堆工具"，而是**把运维领域拆成 Agent 粒度的能力单元**：告警诊断、指标分析、PromQL/InfluxQL 生成、Grafana 看板、CMDB 资产、天巡巡检、变更影响、SLO 分析各自独立部署，再通过 A2A/AGUI 协议由一个动态装配的总入口 Agent 做 LLM 自主委派。
>
> 我在其中做得最有工程含量的三块是：**①上下文压缩的七层体系**（列式输出表示层 → 结构化截断 + COS 卸载 → 说明书侧压缩 → summarization elide → 超限自适应压缩重试 → 摘要替代历史 → 场景化裁剪）。其中 L0 不是“任何 JSON 数组自动压缩”，而是少数工具主动采用 `compact_table` 或 v3 拓扑紧凑契约；L1 才按最终结果的字节大小决定是否截断。它显著降低非流式链路因上下文超限中断的概率，但 L4 尚未覆盖流式 `Stream` 主链路，不能夸大为所有会话都“透明自愈”（完整触发矩阵见第一篇之一 §1.1）；**②mcporter 路线**，让 MCP 工具零 tool-schema 占用；**③数字分身的运行时人格装配**，一个 Agent 实例通过 `BeforeAgent` 钩子链服务 N 个不同权限边界的分身。
>
> 同时我很清楚它的短板：**没有工具级权限体系与 HITL 审批**、**没有效果评测集**、**RAG 融合排序有技术债**——这三条是我认为下一阶段的P0。
