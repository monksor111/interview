## A · 数据同步层（5 条）

**A1 · Kafka commit 策略已明确**（原短板已修正）
- 代码明示 `enable.auto.commit: false`（`unified_incr_sync_consumer.go:66`）
- **不是短板** —— 原推演的"未明确"实际已经是 manual commit
- 面试可以主动指出："**乐观锁 + manual commit = 实用 exactly-once**"

**A2 · event_time 依赖 NTP** ⚠️ P1
- 现象：数据源 NTP 漂移 → 新事件反而 sync_version 更小 → 被跳过
- 修法：ingest_time fallback
- 改动量：<100 行

**A3 · 全量与增量 sync_version 语义不完全对齐** P2
- 全量 = time.Now()、增量 = event_time
- 修法：全量传递数据源 event_time
- 改动量：300 行

**A4 · DELETE 语义未标准化** P1
- INCR_SYNC_DESIGN §4.2 提"BeforeDelete (可选)"，规则未明确
- 修法：明确"event_time >= current sync_version 才删"
- 改动量：<50 行

**A5 · Kafka session.timeout 10s 可能过短** P2
- 修法：调到 30s
- 代价：故障发现慢

## B · 元数据 SPI（3 条）

**B1 · Pull 周期盲区** P1
- 现象：新扩容资源 10 分钟才可见（云梯甚至一天）
- 修法：Push 通道 + 分级拉取

**B2 · SPI 版本管理缺失** ⚠️ **P0**

- 修法：`/v1/entities` 版本号 + 多版本并存
- 改动量：<100 行

**B3 · 分页 offset 而非 cursor** P2
- 现象：分页期间数据变动导致重复或漏
- 修法：游标分页
