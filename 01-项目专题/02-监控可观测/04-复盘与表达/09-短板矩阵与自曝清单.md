# 短板矩阵：从 Global 源码直接看到的债

| 优先级 | 事实 | 影响 | 建议 |
|---|---|---|---|
| P0 | 写入失败无 durable retry；源码明确 TODO | 数据永久缺口 | Outbox/Kafka 或磁盘 WAL，按目标独立重放 |
| P0 | XStor 与 VM 在同一 worker 串行写 | 一个库慢拖另一库 | 独立 worker pool、熔断、分目标队列 |
| P0 | VM 转换仅放行 storageId=1 且有双开关 | 配置误解导致“以为写 VM 实际未写” | 启动自检、配置审计和写入覆盖率告警 |
| P1 | 标签值截断、标签数上限 | 防爆炸但可能 series 碰撞/维度缺失 | 拒绝/采样并记录原因，改为指标级 schema 治理 |
| P1 | 流 Kafka 队列满时同步退化 | 下游慢拖 API P99 | 明确优先级、隔离 producer、持久 outbox |
| P1 | CK 读写异步且消费端不在仓库 | 读己之写不可保证 | 展示延迟水位、按时间窗回退 XStor |
| P1 | CK planner 功能子集小 | 一些指标/表达式回退 XStor | 可观测回退原因，补一致性测试后扩展 |
| P1 | 分布式 optimizer 仅一个 endpoint | 没有 TSID/分片查询并行 | 先构建分片元数据与 multi-endpoint 调度 |
| P2 | SuperCache 有刷新延迟 | 新配置暂时不生效 | 提供版本号、主动刷新、灰度可见性 |
| P2 | 自动注册首批数据丢弃 | 新指标冷启动缺点 | 注册 intent 携带少量缓冲样本或回补 |
| P2 | Redis batching 每批起 goroutine | 极端负载下 goroutine 激增 | 为批执行加并发上限和 context |
| P2 | 告警历史和通知非事务 | 双副作用不一致 | 重试/补偿与审计对账 |

## 主动表达模板

“我不会把现在的双写说成强一致：它只是同一 worker 的顺序调用，失败没有可靠重放。这是当前最重要的工程债。已有的保护是按库队列、100 worker、有界重试和指标观测；下一步应优先做目标隔离与 outbox，而不是继续堆并发。”

以上均为代码可见事实；XStor 内核 CPU 占比、VM 集群容量等属于外部系统资料，应另附来源，不混入本表。
