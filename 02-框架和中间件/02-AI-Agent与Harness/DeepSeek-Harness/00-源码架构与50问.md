## 一句话定位

DSH 是一个基于 Cordis 的可组合 Agent harness：模型、工具、会话日志、主循环、持久化和 UI 都是插件；模型看到的上下文由仅追加的会话事件日志派生。它强调“可替换能力接缝 + 可回放事实流”，而不是把功能固化进一个私有主循环。

## Cordis 插件如何协作：服务、事件与生命周期

`Context` 是一棵运行中插件树共享的服务访问入口，不是让插件彼此直接 import 实现类的全局对象。提供方把服务实例注册到稳定 key，例如 `SessionStore` 通过 `super(ctx, 'sessions')` 提供 `ctx.sessions`；消费者声明 `static inject = ['sessions']` 后调用该接口。一个名为 `test` 的服务只有显式注册为 `test` 后才可由 `ctx.test` 访问；服务随其插件和所属 context 生命周期消失。

```ts
class TestService extends Service {
  constructor(ctx: Context) { super(ctx, 'test') }
  greet(name: string) { return `Hello, ${name}` }
}

class Consumer extends Service {
  static inject = ['test']
  constructor(ctx: Context) { super(ctx); ctx.test.greet('yaao') }
}
```

事件用于广播事实或在既定阶段插入策略。事件所属的核心包先用 TypeScript declaration merging 扩展 Cordis 的 `Events` 接口；这只声明事件名和参数类型，不会生成运行时事件总线。运行时由发布方 `ctx.emit(...)` 发出，订阅方用 `ctx.on(...)` 注册回调；同一棵 context 树中所有匹配的监听器都会收到通知，插件卸载、热更新或启动回滚时监听器自动撤销。

```ts
declare module '@deepseek-ai/cordis' {
  interface Events {
    'session/event'(session: Session, event: SessionEvent): void
  }
}

ctx.on('session/event', (session, event) => {
  // session 和 event 由事件名自动推导出类型
})
```

`session/event` 的实际链路是：`session.append()` 先提交内存中的追加日志，`SessionStore` 再发出 `ctx.emit('session/event', session, event)`，持久化、标题、遥测和 UI 等插件各自订阅并处理。它是通知型事件，不能回滚已追加的日志；耗时工作通常只入队，随后由 `session/flush` 等等待型事件完成持久化。事件名是公共协议：不同语义不得复用同一名称，但多个生产者或消费者可共同遵守同一协议。

| 机制 | 典型用途 | 调用方是否等待 |
|---|---|---|
| `emit` | 已发生事实的通知，如 `session/event` | 否 |
| `parallel` | 必须完成的一组独立工作，如 flush | 等待全部完成 |
| `serial` | 有顺序要求的协调 | 按顺序等待 |
| `waterfall` | 可改写或短路下游的中间件，如 `agent/request`、`tools/pre-execute` | 监听器通过 `next()` 委托下游 |

## 50 个常见设计问题：用 DSH 源码回答

### A. 架构与可扩展性

**Q1：Agent 的“核心”应当是什么？**  
DSH 没有不可替换的业务核心；Cordis 插件在共享 `ctx` 上贡献服务、类型化事件和可撤销 effect。模型适配器、工具注册、日志与 agent-loop 都可由配置替换。参见 [architecture.md](/Users/yaao/Documents/code/AI-agent/deepseek-harness/docs/architecture.md)。

**Q2：新增能力时，怎么避免不断改主循环？**  
优先挂到已声明的扩展点：模型注册到 `ctx.llm`，模型可见能力注册到 `ctx.tools`，拦截运行中行为使用 `agent/*` 或 `tools/*` 事件。DSH 将“修改 loop”视为需要同步更新架构图的例外，而不是默认方案。[扩展点表](/Users/yaao/Documents/code/AI-agent/deepseek-harness/docs/architecture.md)

**Q3：可替换能力的最小完整设计是什么？**  
不是只抽一个 interface。DSH 定义 capability seam：Service Definition（接口）、Provider（实现）、Consumer（消费者，常是模型工具）三角色齐全，才能让切换提供方真正影响产品。[能力接缝说明](/Users/yaao/Documents/code/AI-agent/deepseek-harness/docs/capability-seams.md)

**Q4：如何同时支持 CLI、Web 与自动化服务而不分叉代码？**  
用 Profile / Bundle / Patch 叠加装配。`dsh-base` 放基础能力，`dsh-web-app` 加浏览器，`dsh-headless` 加一次性 runner；profile 与 overlay 决定实际插件树。[Profile 文档](/Users/yaao/Documents/code/AI-agent/deepseek-harness/docs/architecture.md)

**Q5：插件热卸载后怎样避免遗留注册？**  
注册必须通过 `ctx.effect()` 或 `ctx.on()`，并返回 disposer；插件卸载时反向撤销。这个纪律比“在全局 map 里塞回调”更适合 HMR 与可重组部署。[根目录约定](/Users/yaao/Documents/code/AI-agent/deepseek-harness/AGENTS.md)

### B. 运行循环与状态机

**Q6：Turn 和 Step 为什么必须分开？**  
Step 是一次模型请求及其工具执行；Turn 是排空一次已接纳输入的 0～N 个 step。分开后，重试、压缩、用户续写与结束策略可以挂在正确粒度，而不是把一切混成“发一条消息”。[Turn flow](/Users/yaao/Documents/code/AI-agent/deepseek-harness/docs/architecture.md)

**Q7：主循环怎样做到可插桩？**  
在 `agent/pre-step`、`agent/request`、`llm/stream`、`tools/pre-execute`、`tools/execute`、`tools/post-execute` 上使用 waterfall 事件；监听器调用 `next()` 继续下游，也可改写或短路结果。[架构流程](/Users/yaao/Documents/code/AI-agent/deepseek-harness/docs/architecture.md)

**Q8：为何要记录“零 step 的 turn”？**  
首次输入被策略拒绝或改写为空时，DSH 仍关闭一个持久 turn。审计系统于是能区分“没有运行”与“运行尝试被策略阻断”。[agent-loop 实现](/Users/yaao/Documents/code/AI-agent/deepseek-harness/packages/core/agent-loop/src/agent.ts)

**Q9：怎样处理 LLM 请求失败？**  
失败 step 收尾后触发 `agent/request-error`；只有监听器返回 retry 动作才启动新轮次。`dsh-compaction-basic` 就在该点处理上下文溢出后的压缩与重试。[compaction-basic](/Users/yaao/Documents/code/AI-agent/deepseek-harness/packages/compaction/compaction-basic/src/index.ts)

**Q10：如何防止无限重复调用工具？**  
DSH 的 `repeat-tool-reminder` 在 `tools/post-execute` 观察结果，并在下一次 `agent/pre-step` 注入提醒；它是独立护栏插件，不污染工具或 loop 实现。[repeat-tool-reminder](/Users/yaao/Documents/code/AI-agent/deepseek-harness/packages/guard/repeat-tool-reminder/src/index.ts)

### C. 会话、记忆与恢复

**Q11：什么应当是 Agent 会话的事实源？**  
DSH 选择仅追加 `SessionEvent` 日志；消息历史由 `deriveMessages()` 投影，避免同时维护“聊天记录”和“运行状态”两份真相。[architecture.md](/Users/yaao/Documents/code/AI-agent/deepseek-harness/docs/architecture.md)

**Q12：为什么流式 chunk 也要持久化？**  
`assistant/chunk` 与最终消息都入日志，因此重启后可按原流式片段回放 UI，而非只恢复最终文本。这个代价换来可观测和回放保真。[Session 类型](/Users/yaao/Documents/code/AI-agent/deepseek-harness/packages/core/session/src/types.ts)

**Q13：怎样保证模型看到的信息可以审计？**  
DSH 的硬规则是“model-visible means logged”：任何进入模型请求的信息必须能由日志重建；加一个模型可见输入就要定义相应 `SessionEventMap` 事件。[architecture.md](/Users/yaao/Documents/code/AI-agent/deepseek-harness/docs/architecture.md)

**Q14：事件词表如何既可扩展又避免未知事件静默丢失？**  
`SessionEventMap` 采用 TypeScript declaration merging；运行时以 `ignorable` 标记区分可安全跳过的事件，格式升级另有版本机制。[session/types.ts](/Users/yaao/Documents/code/AI-agent/deepseek-harness/packages/core/session/src/types.ts)

**Q15：如何支持 fork、resume 与 transcript？**  
它们都从同一事件流派生，而不是复制一套业务状态；Session 服务提供 `fork(source, boundary, childSessionId)`。日志先行使分支边界可审计。[架构扩展点](/Users/yaao/Documents/code/AI-agent/deepseek-harness/docs/architecture.md)

### D. 上下文工程与压缩

**Q16：上下文压缩应在何时运行？**  
DSH 在 `agent/pre-step`、即派生请求之前处理 token 压力，而非模型报错后才盲目截断；这样工具结果修剪和压缩结果都能进入下一次请求。[compaction-basic](/Users/yaao/Documents/code/AI-agent/deepseek-harness/packages/compaction/compaction-basic/src/index.ts)

**Q17：压缩如何保持可追溯？**  
压缩替换消息带 `compactCheckpointSource(compactionId, sourceCommandId)`，把替换文本与其压缩事务身份关联，避免“摘要从哪里来”不可解释。[checkpoint.ts](/Users/yaao/Documents/code/AI-agent/deepseek-harness/packages/compaction/compaction/src/checkpoint.ts)

**Q18：为什么工具结果不能直接粗暴截断？**  
DSH 将工具结果修剪做成独立 `compaction-tool-result-pruner`，在保留结构性信息的前提下减少 token；它属于上下文策略，而非工具语义本身。[pruner](/Users/yaao/Documents/code/AI-agent/deepseek-harness/packages/compaction/compaction-tool-result-pruner/src/index.ts)

**Q19：系统提示怎样实现可组合？**  
PromptSection、动态 PromptContext、工具 schema、变量插值和 `system-prompt/assemble` waterfall 分层组装；任一插件只贡献自己负责的片段。[系统提示子系统](/Users/yaao/Documents/code/AI-agent/deepseek-harness/docs/subsystems/system-prompt.md)

**Q20：提示词变量缺失应当如何处理？**  
DSH 倾向在可判定时 fail loud，而不是用隐式空值兜底；这能尽早暴露错误配置，避免模型在不完整约束下“看似正常”地运行。[AGENTS.md](/Users/yaao/Documents/code/AI-agent/deepseek-harness/AGENTS.md)

### E. 工具、权限与执行环境

**Q21：一个面向模型的工具需要哪些层？**  
除了 name/description/schema，还要有作用域可见性、pre/execute/post 管道、结果物化、展示意图和审计事件。DSH 不把“函数调用成功”当作工具设计的终点。[tools 子系统](/Users/yaao/Documents/code/AI-agent/deepseek-harness/docs/subsystems/tools.md)

**Q22：权限检查放在哪里？**  
在 `tools/pre-execute` 作出 allow/deny 决策，执行后再经 `tools/post-execute` 处理结果；这允许审批、策略与脱敏插件组合，而不用每个工具自行实现权限分支。[tools 接口](/Users/yaao/Documents/code/AI-agent/deepseek-harness/packages/core/tools/src/index.ts)

**Q23：如何避免“工具已被拦截但仍执行”？**  
工具注册表在 pre-execute 后还有单调 guard；该 guard 不能被后续扩展重新放宽，适合安全不可逆的限制。[tools/index.ts](/Users/yaao/Documents/code/AI-agent/deepseek-harness/packages/core/tools/src/index.ts)

**Q24：Shell、子进程、终端与 sandbox 为什么要拆开？**  
Shell 是命令语义，subprocess 是进程树执行，terminal 是持久会话，sandbox 是约束执行环境；分离后本地或远程 sandbox 的替换不会迫使工具与 UI 改写。[架构说明](/Users/yaao/Documents/code/AI-agent/deepseek-harness/docs/architecture.md)

**Q25：文件系统 provider 与 shell provider 必须一致吗？**  
应共享同一执行世界；否则模型在 A 环境读取、在 B 环境执行会造成路径和状态错位。DSH 的 capability seam 明确将这类 provider 的一致性作为设计目标。[capability-seams.md](/Users/yaao/Documents/code/AI-agent/deepseek-harness/docs/capability-seams.md)

### F. 人机协作、计划与任务状态

**Q26：Plan 模式应该只是 prompt 吗？**  
不是。DSH 的 plan-mode 将状态写入 SessionEventMap，并在接受 step 时由 `agent/pre-step` 注入规则；状态因此可回放、可审计，不是瞬时 UI 开关。[plan-mode 源码](/Users/yaao/Documents/code/AI-agent/deepseek-harness/packages/plan/plan-mode/src/index.ts)

**Q27：用户中途改变方向，怎么让模型在正确时机看到？**  
`steer()` 把消息送入 next-step 队列：当前 step 完结后先处理它；`followup()` 是新 turn，`inject()` 只暂存且不唤醒。三种语义不能混成一个 send API。[Agent 接口](/Users/yaao/Documents/code/AI-agent/deepseek-harness/packages/core/agent/src/runtime-types.ts)

**Q28：取消任务时是否应清空所有待办输入？**  
取决于语义。`cancel(cause, { keepInbox: true })` 支持只中止当前活动而保留未处理输入，适合暂停或策略重启；默认行为可用于明确终止。[Agent 接口](/Users/yaao/Documents/code/AI-agent/deepseek-harness/packages/core/agent/src/runtime-types.ts)

**Q29：Todo 是 UI 装饰还是运行时数据？**  
DSH 的 todo 写入有 schema、projection 和持久事件；任务进度可以在重启后恢复，而非只显示在当前页面。[tool-todo](/Users/yaao/Documents/code/AI-agent/deepseek-harness/packages/todo/tool-todo/src/index.ts)

**Q30：并行 in-progress 待办如何避免成为隐藏假设？**  
`allowParallelInProgress` 是明确配置字段且经 schema 校验；策略可按部署改变，而不是在实现里藏一个常量。[tool-todo](/Users/yaao/Documents/code/AI-agent/deepseek-harness/packages/todo/tool-todo/src/index.ts)

### G. 多 Agent 与长任务

**Q31：子 Agent 的抽象应是什么？**  
DSH 将 Subagent 建成 provider 可替换的 seam：可用进程内 fork、独立 driver、ACP 等不同提供者，但上层统一使用 subagent 服务与委派工具。[subagent 子系统](/Users/yaao/Documents/code/AI-agent/deepseek-harness/docs/subsystems/subagent.md)

**Q32：父子取消如何传播？**  
continuation 管理器在父任务收敛或取消时桥接到 child 的 `cancel`，并记录关系与结算，避免子任务成为失控后台进程。[continuation.ts](/Users/yaao/Documents/code/AI-agent/deepseek-harness/packages/subagent/subagent/src/continuation.ts)

**Q33：何时 followup，何时 inject 子任务结果？**  
若结果应立即推进父 agent，用 wakeup 交付并 `followup()`；只应作为下一次请求的背景则 `inject()`。DSH 在 continuation 中按 delivery 语义区分两者。[continuation.ts](/Users/yaao/Documents/code/AI-agent/deepseek-harness/packages/subagent/subagent/src/continuation.ts)

**Q34：长任务恢复靠什么？**  
不仅是 TODO：持久事件流、明确 checkpoint policy、可回放 session 和可续行子 agent 共同构成恢复基础。`session-checkpoint-policy` 在 pre-step 等节点保存策略状态。[checkpoint-policy](/Users/yaao/Documents/code/AI-agent/deepseek-harness/packages/session/session-checkpoint-policy/src/index.ts)

**Q35：为什么“用多 Agent”不能等同于并行？**  
多 agent 还涉及继承什么上下文、结果如何交付、谁负责取消与结算。DSH 将这些写进 subagent provider 与 continuation，而不是只提供一个异步函数池。[subagent](/Users/yaao/Documents/code/AI-agent/deepseek-harness/packages/subagent/subagent/src/index.ts)

### H. LLM、可靠性与成本

**Q36：模型 provider 怎样替换而不影响上层？**  
LLM 是 `ctx.llm` seam；Agent loop 消费统一的 message 与 stream 词表，provider 只负责协议适配。这样切模型不需要改工具调用和 session 事件格式。[architecture.md](/Users/yaao/Documents/code/AI-agent/deepseek-harness/docs/architecture.md)

**Q37：重试为什么不能只包一层 HTTP client？**  
模型失败与上下文状态有关。DSH 让 `agent/request-error` 能拿到 agent、turn、step、provider、failure、retry policy 和 AbortSignal，策略可据此压缩、退避或终止。[runtime-types.ts](/Users/yaao/Documents/code/AI-agent/deepseek-harness/packages/core/agent/src/runtime-types.ts)

**Q38：怎样限制单次工具卡死拖垮整轮？**  
timeout policy 是单独的 guard 包，利用工具流水线和 AbortSignal 实施；超时策略能按部署配置，不必内嵌进每个执行器。[timeout-policy](/Users/yaao/Documents/code/AI-agent/deepseek-harness/packages/guard/timeout-policy/src/index.ts)

**Q39：Token 计量该在哪一层？**  
DSH 将 token-meter 放在 LLM capability 侧，并让 compaction 在请求前基于压力决策；计量、压缩与 provider 适配因此可独立演进。[包结构](/Users/yaao/Documents/code/AI-agent/deepseek-harness/packages/README.md)

**Q40：配置默认值的正确位置？**  
应由拥有该配置的实现显式 `resolve(request)`，而不是在深层 `run()` 里隐式 `?? default`；否则调用方无法知道最终执行规格。[AGENTS.md](/Users/yaao/Documents/code/AI-agent/deepseek-harness/AGENTS.md)

### I. 可观测性、测试与演进

**Q41：Agent 可观测性的最小单元是什么？**  
不是只记最终 answer；至少要能追踪 turn、step、模型 chunk、tool call/result、inbox 与取消原因。DSH 将多数关键状态落为 SessionEvent。[architecture.md](/Users/yaao/Documents/code/AI-agent/deepseek-harness/docs/architecture.md)

**Q42：UI 如何不与运行时状态双写？**  
UI 订阅 `session/event` 并由日志投影渲染；重连或回放时重建相同状态。这使 UI 成为事实流的消费者，而不是另一份真相。[Session 架构](/Users/yaao/Documents/code/AI-agent/deepseek-harness/docs/subsystems/session.md)

**Q43：如何测试模型可见行为而不依赖真实 API？**  
仓库提供 `llm-replay`、snapshot 与 assembled application 测试支撑；关键用户可见行为应通过可运行例子的无密钥快照验证。[AGENTS.md](/Users/yaao/Documents/code/AI-agent/deepseek-harness/AGENTS.md)

**Q44：为什么类型事件比任意 JSON event 更适合大型 Agent？**  
事件名、payload 和消费者可被编译器与生成目录校验；新事件若未进入持久词表会尽早失败，减少“生产回放才发现字段不存在”。[known-event-types.ts](/Users/yaao/Documents/code/AI-agent/deepseek-harness/packages/core/session/src/known-event-types.ts)

**Q45：Agent 自修改应如何收口？**  
DSH 把自修改限制为 Cordis 插件检查、挂载与运行器能力，而不是让模型任意改核心 loop；改动仍处于可配置、可加载、可卸载的插件边界内。[extensions 包](/Users/yaao/Documents/code/AI-agent/deepseek-harness/packages/extensions)

### J. 面试式取舍题

**Q46：DSH 最大优点是什么？**  
它把“模型可见上下文、运行过程和持久事实”统一到事件流，并用 plugin/seam 让具体能力替换不波及主循环；这对可审计、可恢复的复杂 Agent 很有价值。

**Q47：最大代价是什么？**  
学习成本高：开发者要同时理解 Cordis 生命周期、scope、事件模式、SessionEventMap 和 provider/consumer 分工。小型单功能 Agent 不一定值得承担这套抽象。

**Q48：什么时候不该采用全事件溯源？**  
若任务是无状态、一次性、没有 resume/audit/UI replay 需求的轻量脚本，追加每个 chunk 与步骤会增加复杂度；可仅保留结构化 trace，再在需求增长时演进。

**Q49：如何把 DSH 思想迁到自研 Agent？**  
优先落地三条：把模型可见输入写成可重建事件；将工具执行前/后定义为明确策略点；把 provider 与 model-facing consumer 分开。不要一开始复制全部插件目录。

**Q50：面试中如何用一句话总结它？**  
“DSH 的关键不在某个 Tool 或 Plan Mode，而是把 Agent 当作可组装的事件驱动系统：插件提供能力，session log 提供事实，waterfall 提供策略插点，因此压缩、审批、子 Agent、恢复和 UI 回放能在同一条可审计链路上协作。”
